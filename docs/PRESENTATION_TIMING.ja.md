# 呈示時刻とブロック境界

PyRetinotopyは、すべての刺激ファミリーで同じ `AbsoluteTimeline` と呈示ループを使います。第1実測flipの時刻を `t0` とし、ラン内でこの起点を固定します。前置注視4秒、周期60秒なら、各周期の目標は `t0 + 4`, `t0 + 64`, `t0 + 124`, ... です。

各flipの直前に、PsychoPyが予測する次のリフレッシュ時刻から `t0` を引き、その累積経過時間に対応する刺激状態を選びます。ブロックごとの実測終了時刻は次の目標計算に使いません。途中の遅れを後続ブロックへ加算しません。

名目60 Hzに対して実際の表示が少し速い場合は、必要に応じて同じ状態を保持します。少し遅い場合や遅延フレームがあった場合は、現在の累積時刻に対応する状態へ追いつきます。「毎flipで名目フレーム番号を必ず1増やす」という制約も外しています。これにより、refreshの微差による後半の早まり／遅れも防ぎます。

## 刺激ファミリーごとの目標

| ファミリー | ラン開始からの累積目標 |
|---|---|
| 楔形・環状 | 前置注視 + 周期番号 × cycle_s |
| バー | 前置注視 + 走査番号 × cycle_s。休止を含め各方向を固定 |
| 楔形＋環状 | 極角と離心度の各周期を、独立に同じt0から計算 |
| multifocal | 前置注視 + 試行番号 × trial_s |
| 子午線・LGN・離心度localizer | 前置注視 + ブロック番号 × block_s |
| HRF | 前置注視 + 周期番号 × cycle_s |

マスク内の各位置の切替も、同じ累積時刻に基づく全区間スケジュールで選びます。表示可能な時刻はリフレッシュで離散化されるため、最寄りの表示フレームへの丸め誤差は残ります。表示機器から眼へ届く光の時刻は、フォトダイオード等で別途検証する必要があります。

## 保存される記録

`block_timing.tsv` は次の列を持ちます。

| 列 | 内容 |
|---|---|
| series / block | 周期・走査・試行・ブロックの種類と番号 |
| planned_onset_s | t0からの目標累積時刻 |
| scheduled_onset_s | 名目refreshに割り当てた時刻 |
| actual_onset_s | 該当状態を表示した実測flip時刻 |
| error_s | 実測 - 目標。負値は予定より早いことを示す |
| frame | 実際のflip通し番号 |

`events.tsv` は個々の刺激状態に `planned_onset` と `onset_error_s` を追加します。`summary.json` の `block_timing.max_abs_error_s` はブロック等の最大絶対誤差です。名目refreshと実refreshが一致しない場合、実flip数と名目フレーム数は一致しないことがあります。ラン時間と境界は累積時刻で維持します。

## 確認方法

実験後、`error_s` をブロック番号または `planned_onset_s` に対して確認します。後半ほど増える傾向がないこと、実験条件に必要な誤差範囲に収まることを確認してください。中止されたランの未到達境界は `n/a` です。

自動試験では、名目60 Hzに対する59 / 59.94 / 60.06 / 61 Hzの20分相当の表示を模擬し、60秒ごとの境界誤差が累積しないことを確認しています。また、途中の1.4秒の停止を模擬し、次のブロック以降へ遅れを持ち越さないことを確認しています。

ここでいう実測時刻はPsychoPyが返す同期時刻で、光学的な測定を代替するものではありません。実験に使用する装置で、通常のラン長と刺激条件に合わせて確認してください。
